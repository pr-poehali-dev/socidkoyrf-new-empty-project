# Соскидкой.рф — инструкция для Юры

## Прочти это первым делом

В проекте есть **Память** — страница владельца по адресу `/owner/memory`.
Её содержимое лежит в `backend/memory/data/*.json`.

**Не читай эти файлы без просьбы владельца.** Там записана история и договорённости,
а не текущее состояние кода. Факты бери из самого кода — он всегда актуален.
Владелец скажет, какой раздел прочесть, если понадобится.

**Твоя обязанность — дописывать память после каждой работы. Сам, без напоминания.**

---

## Куда что записывать

| Что произошло | Файл | Поля |
|---|---|---|
| Доделал задачу, она работает | `done.json` | date, title, status, details |
| Появилась задача на будущее | `plans.json` | priority, title, status, details |
| Приняли решение «делаем так, а не эдак» | `decisions.json` | date, topic, decision, why, rejected, status |
| Сделал переиспользуемый кусок интерфейса | `blocks.json` | name, file, used, details |
| Завёл сервис, домен, ключ | `access.json` | service, where, status, note |
| Поставил костыль, что-то временно или сломано | `issues.json` | severity, title, status, details, fix |
| Ввели новое слово в обиход | `glossary.json` | term, meaning |

`instruction.json` и `vk_setup.json` — инструкции для владельца, меняй только по его просьбе.

## Правила записи

1. **Дописывай сразу после работы**, не дожидаясь просьбы. Новые записи — в начало списка.
2. **Решение записывай с причиной.** Без «почему» запись бесполезна: через месяц никто не вспомнит,
   и решение переиграют заново. Поле `rejected` — что рассматривали и отвергли.
3. **Костыль записывай честно** в `issues.json`, даже если он твой. Поле `fix` — чем заменить.
4. **Пиши по-человечески.** Владелец не программист: «вход через ВКонтакте», а не «OAuth-флоу».
   Никаких путей к файлам и названий библиотек в тексте, который он читает.
5. **Никаких паролей, ключей и токенов** в памяти. Только названия полей из хранилища секретов.
6. **Ничего не удаляй.** Устарело — меняй `status` на «пересмотрено» или «заменено».
7. Формат дат: `ГГГГ-ММ-ДД`.

## После правки памяти

Вызови `sync_backend` — иначе изменения не доедут до страницы.

## Главное о проекте

Площадка товаров со скидками. React + Cloud Functions + PostgreSQL.

- Вход без паролей, через социальные сети. Сейчас ВКонтакте, дальше Яндекс и Telegram.
- Владелец — конкретный аккаунт, не роль. Узнаётся по `OWNER_VK_ID` из секретов.
- Панель управления `/owner`, вход только после второго подтверждения (`/vault`).
- Порядок проверки прав строгий: вошёл → активен → второй вход → владелец ли.
- Сайт собираем блоками, не отдельными страницами.
